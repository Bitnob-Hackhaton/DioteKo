`backend-nest/src/modules/bitnob/` structure after **Increment 3** of the Bitnob plan (payout rework).

**Why:** Increment 2 kept one `BitnobService` with an unverified `/api/v1/payouts...` best-effort payout path. Increment 3 replaced it entirely with a verified 3-step flow and a security-hardened certificate path.

**How to apply:** payout HTTP calls go on `BitnobPayoutsService` (repo-free); local `bitnob_payouts` persistence lives with the callers (`BitnobMoneyController` for the raw admin path, `AdminCertificatesService` for the cert path). Services log `[START]`/`[RESULT]` only.

- **`BitnobService` + `bitnob.service.ts` DELETED.** Also deleted: `bitnob.controller.ts`, `dto/execute-payout.dto.ts`. `dto/create-payout-quote.dto.ts` rewritten (no `amount`/`reference` fields — reference is server-derived).
- **`BitnobPayoutsService`** (`services/bitnob-payouts.service.ts`) — `createQuote` / `initializePayout` / `finalizePayout` / `getPayout` / `listPayouts` / `accountLookup` / `supportedCountries` / `countryRequirements` / `banks` / `limits`. Injects `BitnobHttpClientService` + `ConfigService` ONLY (no repo). Builds snake_case wire bodies explicitly. `finalizePayout` throws `ForbiddenException` first-line when `bitnob.environment === 'production'`. `initializePayout` builds `callback_url` from `app.baseUrl` server-side (never caller-supplied); non-HTTPS rejected only in production.
- **`BitnobMoneyController`** (`controllers/bitnob-money.controller.ts`, was `BitnobController`) — class `@Roles(ADMIN)` ONLY (raw money path; `JwtPayload` has no `organizationId` so it can't be issuer-scoped). Routes: `POST payouts/quotes` (persists a `bitnob_payouts` row first, status `quote`, `reference = dkpayout_<row id>`), `POST payouts/:id/initialize` (`:id` = our row id; loads `quoteId`/`reference` from it; body = `InitializePayoutDto` with `BankBeneficiaryDto`), `POST payouts/:id/finalize`, `GET payouts` (proxied, beneficiary stripped per item), `GET payouts/:id` (local-row projection, no Bitnob call), `GET payouts/account-lookup`. Injects `@InjectRepository(BitnobPayout)` directly.
- **`BitnobReadController`** — added `GET payouts/{supported-countries, supported-countries/:country, banks/:countryCode, limits}` (class tier issuer/admin — reference data). **MUST be registered before `BitnobMoneyController`** in `bitnob.module.ts` `controllers[]` so its static `payouts/*` segments beat `payouts/:id`.
- **`payouts.util.ts`** — `mapBitnobPayoutStatus(status, logger?)` (UPPER→lowercase; **unknown/empty → `'failed'`** + `logger.warn`, never a pass-through — a bad status would never be terminal and would brick the cert), `reconcilePayoutStatus(remote, logger?)` (map + downgrade a lapsed `QUOTE` → `expired`), `payoutStatusRank` (forward-only ordering `quote<initiated<finalizing<pending<processing<terminal`, unknown=-1), `isTerminalPayoutStatus`, `stripPayoutPii` (drops keys `/^(beneficiary|account|iban|bank_account)/i`), `summarizePayoutError` (PII-safe: `BitnobApiError` → only `code`/`title`/`type`; **any other `Error` → `err.name` ONLY**, never `.message` — `unwrapBitnob` throws `Error(message)` on a 200-but-`success:false` body and that message can echo an account number). **`payouts.constants.ts`** — shared DTO vocabularies.
- **`bitnob-http-client.service.ts`** — error-branch log uses private `summarizeBitnobError(body, fallbackMsg)` → logs ONLY `{code,statusCode,title,type}` (drops `message`/`error`/`detail`). `BitnobApiError.message` never interpolates the body.
- **`finalizing` local-only transient status** — set by an atomic `repo.update({ id, status: 'initiated' }, { status: 'finalizing' })` compare-and-swap at the top of BOTH `AdminCertificatesService.finalizeBitnobPayoutForCertificate` and `BitnobMoneyController.finalize`, BEFORE the pre-poll + Bitnob call. `affected !== 1` → `ConflictException`. On success → `processing`; on any error (prod gate / read failure / Bitnob reject) → reverted to `initiated`. This is the CLAUDE.md §11 prerequisite for enabling prod finalize.
- **Webhook state-machine guard** (`bitnob-webhook.service.ts`): `payouts.initialized → 'initiated'` (was `'processing'`). `dispatchPayoutEvent` now: unknown event type → ignore+warn; row already terminal → ignore; `payoutStatusRank(mapped) <= payoutStatusRank(current)` → ignore (forward-only). `reconcile` deliberately has NO forward-only guard (it's the authoritative manual re-sync).
- **`getPayoutOrThrow`** wraps `getPayout` in finalize/reconcile → transient Bitnob read failure = `ServiceUnavailableException` (503) + error summary in `raw_result`, not a 500.
- Audit (`recordPayoutAudit` / money controller `audit`) is **best-effort** — a failed `access_logs` write warns, never corrupts the payout result. Raw money routes (`initialize`/`finalize`) now write audit rows too (`actor_type='system'`, `actorUserId = @CurrentUser().sub`, `metadata: { reference }`). `BitnobModule` imports `ConsentModule` for `AccessLogService`.
- **`bitnob_payouts` entity/table reworked** (migration `1787059800000-ReworkBitnobPayouts`): added `reference`, `source`, `admin_certificate_ref_id` (FK→`admin_certificates_refs` `FK_bitnob_payouts_admin_certificate_ref`, **ON DELETE RESTRICT** — a money row must not orphan; entity `onDelete: 'RESTRICT'`), `raw_quote`, `raw_result` (jsonb); `organization_id`/`bitnob_payout_id`/`amount` → nullable; `status` default `'quote'`; partial unique indexes `UQ_bitnob_payouts_active_cert ON (admin_certificate_ref_id) WHERE status NOT IN ('failed','expired')` (failed+expired are re-quotable, don't block) and `UQ_bitnob_payouts_reference ON (reference) WHERE reference IS NOT NULL` (idempotency-key backstop). Migration `up()` TRUNCATEs, `down()` `DELETE`s first (both discard rows by design). `migration:generate` drift-check is clean — TypeORM accepts `WHERE ... NOT IN (...)` matching PG's normalized `<> ALL (ARRAY[...])`.
- **`bitnob-payout.entity.ts` now imports `AdminCertificateRef`** (`@ManyToOne`) — entity-level cross-import only; `BitnobModule` still does NOT import `AdminCertificatesModule` (one-directional: `AdminCertificatesModule` imports `BitnobModule` and `forFeature([BitnobPayout])`).
- **Cert-path payout** = `AdminCertificatesService.{createBitnobPayoutForCertificate, finalizeBitnobPayoutForCertificate, reconcileBitnobPayoutForCertificate}`. Controller: `POST :certificateId/bitnob/payouts` (`@Roles(ISSUER, ADMIN)`), `.../payouts/finalize` + `.../payouts/reconcile` (`@Roles(ADMIN)`). DTO `CreateBitnobPayoutForCertificateDto` carries NO beneficiary/customerId/organizationId — beneficiary resolved from `BITNOB_PAYOUT_BENEFICIARY_{ACCOUNT_NUMBER,ACCOUNT_NAME,BANK_CODE,COUNTRY}` config (→ 500 if any missing). Create = 409 pre-check (`status: Not(In(['failed','expired']))`) → `dataSource.transaction` [insert `bitnob_payouts` `'quote'` + `payments` `purpose_type='admin_certificate_bitnob_payout'` `'pending'`] → quote → initialize → row `'initiated'`. Never chains finalize. Transaction wrapped so a concurrent-race 23505 (`QueryFailedError` code `23505` on either unique index) → `ConflictException`, not 500. If the quote step throws (no `bitnobPayoutId` yet) the catch sets `status='failed'` so the cert isn't permanently bricked. `reconcile` uses `reconcilePayoutStatus` (lapsed `QUOTE` → `expired`). `access_logs` row (`actor_type='system'`, `action='payout'` — new `AccessLogAction.PAYOUT`, no migration) on the `initiated` + terminal transitions only, `metadata` exactly `{certificateId, reference}`.
- New config: `app.baseUrl` (`APP_BASE_URL`, required at boot), `bitnob.environment` (`BITNOB_ENVIRONMENT` `sandbox|production`, `@IsIn`, default sandbox), `bitnob.payoutBeneficiary.*` (warn-only).
- Kept from Increment 2: `BitnobIdentityService`, `BitnobBalancesService`, `BitnobRatesService`, `BitnobTransactionsService`, `BitnobWebhookService`, `bitnob_trades`/`bitnob_cards` entities. `unwrapBitnob` unchanged.
